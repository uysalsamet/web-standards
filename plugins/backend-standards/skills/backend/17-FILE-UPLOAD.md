# 17 — File Upload, Serving, and Fetching External Resources

> File upload is where a web application **gives the attacker the most control**: they
> choose the content, they choose the name, they choose the size. This is why nearly
> every rule here revolves around "don't use what the client sent, generate it
> yourself."
>
> MinIO/S3 is assumed as the object store; files are not kept on the application
> server's disk.

---

## 1. Accepting: what is taken in

**[FILE-01] MUST:** Every upload endpoint has an **explicit size limit**. The general
4 MB body limit ([RES-05]) is set **specifically for that endpoint**; the general limit
is not raised.

```go
// Limit specific to the upload endpoint. Raising the general limit leaves ALL
// endpoints vulnerable.
func UploadLimit(max int64) gin.HandlerFunc {
	return func(c *gin.Context) {
		c.Request.Body = http.MaxBytesReader(c.Writer, c.Request.Body, max)
		c.Next()
	}
}
```

**[FILE-02] MUST:** Files are processed **as a stream**, never loaded fully into
memory. Read piece by piece with `multipart.Reader` and stream directly to the object
store.
> Loading a 200 MB upload into memory means a single request causes an OOM at the
> 256 MB container limit ([PERF-04]). The attacker does not need anything clever; a
> large file is enough.

**[FILE-03] MUST NOT — trusting the `Content-Type` header.** The client can write
whatever it wants there. What the content **actually** is gets checked:

```go
// Look at the first 512 bytes: http.DetectContentType infers the type from magic
// bytes. The client's Content-Type header is informational, NOT the decision.
head := make([]byte, 512)
n, _ := io.ReadFull(file, head)
detected := http.DetectContentType(head[:n])

if !allowedTypes[detected] {
	badRequest(c, "this file type is not accepted")
	return
}
```

**[FILE-04] MUST — allowed types are a whitelist**, not a blacklist:
```go
// WHITE list: you enumerate what passes. A black list is always incomplete —
// there is always an extension/type you did not think of.
var allowedTypes = map[string]struct{}{
	"image/jpeg":       {},
	"image/png":        {},
	"application/pdf":  {},
}
```

**[FILE-05] MUST NOT — accepting SVG as an "image."** SVG is an **XML document**
and can run `<script>`. If it must be accepted, it is either sanitised on the server or
served only with `Content-Disposition: attachment` ([FILE-11]).

**[FILE-06] MUST NOT — extracting an archive on the server** (unless required). If
it is required:
- The total extracted size and file count are limited (**zip bomb**: a 1 MB archive can
  expand to 10 GB)
- Every entry's path is validated — an entry containing `../` is rejected
  (**zip slip**: an archive can write a file outside the target directory)
- Entries containing symbolic links are rejected

## 2. Naming and storage

**[FILE-07] MUST — the file name the client sends is never used as a file-system
path or object key.** The server generates a new name:

```go
// The key is generated by the SERVER. The client's name is only stored as a
// "display name" in a separate column.
// Why: "../../etc/passwd", "..\\..\\web.config", NUL bytes, unicode normalisation
// tricks, and excessively long names — all of these come in through the file name.
objectKey := fmt.Sprintf("uploads/%s/%s%s",
	time.Now().UTC().Format("2006/01"),   // avoid millions of objects in one directory
	uuid.NewString(),
	safeExt(detected),                     // extension is derived from the DETECTED type
)
```

**[FILE-08] MUST:** The original file name is stored in a separate column, its length
is limited ([SEC-13]), and it is escaped when displayed. When placed in the
`Content-Disposition` header on download, **RFC 5987 encoding** is used — a file name
with Turkish characters breaks the header otherwise.

**[FILE-09] MUST:** Files are kept **in the object store** (MinIO/S3), not on the
application container's disk.
> **Why:** the container disk is ephemeral (the stateless rule, [PERF-29]); it is lost
> on restart and not shared between replicas. Also, write access to the application
> disk can turn an upload flaw directly into code execution.

**[FILE-10] MUST:** The object store is **not public**. The bucket is closed by
default; access is granted through the application, or via a **short-lived presigned
URL**.

## 3. Serving: the most critical section

**[FILE-11] MUST — a user upload is never served from the main domain.** One of
three options is used:

1. **A separate domain** (`files.example.gov.tr`) — the safest option
2. Through the application, **always** with these headers:
   ```
   Content-Disposition: attachment; filename*=UTF-8''<encoded-name>
   X-Content-Type-Options: nosniff
   Content-Security-Policy: default-src 'none'; sandbox
   Content-Type: application/octet-stream   (when it does not need to be viewed)
   ```
3. A presigned URL straight from the object store (if the store is on a separate
   domain)

> **Why this matters so much:** an HTML/SVG file served from the main domain runs in
> that domain's **origin**. That means the uploaded file can read the session cookie
> and make requests on the user's behalf — the classic "stored XSS via file upload."
> Without `nosniff`, the browser can sniff the content and treat it as `text/html`;
> without `attachment`, it opens in the browser too.

**[FILE-12] MUST:** Downloading goes through an authorisation check **every single
time** ([GEN-10]). "Whoever knows the URL can access it" is not authorisation — even if
the UUID is unguessable, URLs get shared, end up in logs, and leak through `Referer`.

**[FILE-13] MUST:** Presigned URL lifetime is kept **short** (default: 5 minutes) and
is granted only for the operation needed (read for reading, write for writing).

## 4. Content processing

**[FILE-14] SHOULD — images are re-encoded.** The uploaded image is decoded and
re-encoded before being stored.
> **Two benefits:** (1) payloads embedded in the image file (polyglot files) are
> stripped. (2) **EXIF data is removed** — the GPS coordinates and device info inside
> EXIF are **personal data** ([KVKK-02]); you do not want to collect and publish them
> unknowingly.

**[FILE-15] MUST:** Decoding an image is **not a safe operation**; resource
consumption is bounded: a maximum pixel size (decompression bomb — a 100 KB PNG can
expand to 25,000×25,000 pixels), a processing timeout, and preferably a separate
worker process.

**[FILE-16] SHOULD:** If there is public (unauthenticated) upload, **virus scanning**
is done (ClamAV or similar). Scanning can be asynchronous; the file stays in a
"pending" state and cannot be downloaded until it is scanned.

**[FILE-17] MUST:** An uploaded file is **never executed under any circumstances** —
not passed as a shell argument, not `exec`'d, not dynamically loaded. If it must be
handed to an external tool (ffmpeg, imagemagick), pass the **server-generated key**,
not the file name, and pass arguments as an array, never concatenated through a shell.

## 5. Fetching external resources — SSRF

This section applies to any place where "import from URL," webhook validation, remote
image fetching, or anything else has **the server make a request to an address
supplied by the user**.

**[FILE-18] MUST:** The server never makes a request directly to a URL the user
provided.
> **Why (SSRF):** the server sits on an internal network. Addresses like
> `http://169.254.169.254/` (the cloud metadata service), `http://localhost:5432`, or
> `http://arnavutkoy-auth-service:3000/` are **unreachable from outside but reachable
> from your server**. An attacker uses your server as a proxy into the internal
> network, bypassing every protection the gateway provides.

**Implementation:**
```go
// 1) Scheme whitelist: only http/https. file://, gopher://, dict:// are FORBIDDEN.
// 2) IP check happens AFTER DNS resolution — "evil.com" can resolve to a private IP.
// 3) Redirects are NOT followed; if they must be, the same check is repeated at every
//    step (the first request can go to a legitimate address, and the redirect to
//    169.254.169.254).
func safeDial(ctx context.Context, network, addr string) (net.Conn, error) {
	host, _, _ := net.SplitHostPort(addr)
	ip := net.ParseIP(host)
	if ip == nil || ip.IsLoopback() || ip.IsPrivate() ||
		ip.IsLinkLocalUnicast() || ip.IsUnspecified() {
		return nil, errors.New("access to this address is blocked")
	}
	return (&net.Dialer{Timeout: 5 * time.Second}).DialContext(ctx, network, addr)
}
```

**[FILE-19] MUST:** An external fetch request has a timeout ([RES-07]), a size limit
(`io.LimitReader`), and a limit on the number of redirects.

**[FILE-20] SHOULD:** Use an **allowlist** where possible: enumerate which domains can
be fetched from. A blacklist (blocking private IP ranges) is correct but incomplete; a
whitelist is exhaustive.

## 6. Quotas, cleanup, monitoring

**[FILE-21] MUST:** Upload endpoints are rate-limited ([RES-01], the "heavy endpoints"
category) and there is a **storage quota** per user/tenant. An unquota'd upload is a
cost with no ceiling.

**[FILE-22] MUST:** Abandoned uploads and **orphaned objects** (record deleted but the
file still there) are cleaned up regularly. Deleting the file must be part of the same
workflow as deleting the record — if it contains personal data, this is also required
by [KVKK-04].

**[FILE-23] MUST:** Upload and download operations are written to the **audit trail**
([AUDIT-01]) — who uploaded what, who downloaded what. Files can contain personal
data.

**[FILE-24] SHOULD:** Metrics to track ([OBS-12]): upload count/size, rejected upload
count and **reason**, storage usage, scan queue depth.

## 7. Verification tests

**[FILE-25] MUST:** The following are tested, and all must be rejected:

```
□ Extension .jpg but content is HTML             → 400
□ Content-Type: image/png declared but it's a PDF → decision based on detected type
□ File name "../../../etc/passwd"                 → server generates the name, no path escape
□ File name with a NUL byte / 500 characters      → 400
□ File 1 byte over the size limit                 → 400 (413 also acceptable)
□ Zero-byte file                                  → 400
□ SVG containing <script>                         → rejected, or served as attachment
□ Zip bomb (high compression ratio)                → 400
□ Unauthorised user downloads someone else's file  → 403
□ Expired presigned URL                           → 403
□ Import from URL: http://169.254.169.254         → blocked
□ Import from URL: an internal service address     → blocked
□ Uploaded file opens as HTML from the main domain → must not open
```

---

## 8. NEVER DO THIS

- ❌ Trusting the `Content-Type` header
- ❌ Filtering extensions/types with a blacklist
- ❌ Turning the client's file name into a file path / object key
- ❌ Keeping the file on the application container's disk
- ❌ Serving a user upload from the main domain without `nosniff`/`attachment`
- ❌ Treating SVG as an "image" without sanitising it
- ❌ Making the object store bucket public
- ❌ "Whoever knows the URL can access it" logic (download with no authorisation check)
- ❌ A long-lived presigned URL
- ❌ Reading the whole file into memory
- ❌ Extracting an archive without limits (zip bomb / zip slip)
- ❌ Decoding an image without a pixel/timeout limit
- ❌ Publishing an image that may contain location data without stripping EXIF
- ❌ Passing an uploaded file to a shell command as a string
- ❌ Making a direct request to a user-supplied URL (SSRF)
- ❌ Following redirects without control
- ❌ Opening an upload endpoint without quota and rate limit
- ❌ Not cleaning up orphaned files
